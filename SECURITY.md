# Security Policy

**The full policy is published at <https://cvelab.tech/security/>**: what is
in scope for this tool and for the cvelab.tech service, what is not, and how
disclosure works. This file covers how to report, which is what GitHub shows
in the repository's Security tab.

This is about vulnerabilities **in CVELab itself**, not the vulnerabilities
CVELab reproduces. Lab services are vulnerable on purpose.

## Reporting a vulnerability

- **In this tool:** privately through
  [GitHub Security Advisories](https://github.com/AndreiIonascu17/cvelab/security/advisories/new),
  or by email to contact@syncbitsoft.com.
- **In cvelab.tech:** by email to contact@syncbitsoft.com.

Do not open a public issue, pull request or discussion for a security report.
Include the version or URL, what you did, what happened, and a minimal
reproduction; remove any API key from a lab directory before attaching it.

## What to expect

| Stage | Target |
| --- | --- |
| Acknowledgement | 3 working days |
| Initial assessment | 10 working days |
| Fix or mitigation plan | 30 days for high severity |

Targets, not contractual commitments. Only the latest release receives
security fixes. Coordinated disclosure, with credit unless you ask otherwise;
there is no bug bounty.
